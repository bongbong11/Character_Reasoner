# Character Reasoner

SillyTavern용 **시트 정규화 테스트 확장**입니다.

현재 단계에서는 캐릭터 / 페르소나 / NPC 시트와 선택한 연결 로어북 항목을 읽어, 이후 장면별 검색에 사용할 수 있는 짧은 구조화 레코드로 변환합니다. Jev 판정, 임베딩 검색, 실제 프롬프트 주입은 아직 하지 않습니다.

## 설치

SillyTavern의 **확장 → 확장 설치**에서 아래 주소를 사용합니다.

```text
https://github.com/bongbong11/Character_Reasoner.git
```

설치 후 새로고침하면 채팅 입력창 주변에 사람 아이콘이 생깁니다.

## 연결

별도 API 키를 저장하지 않습니다.

1. 기존 씬판독기에 저장된 `SillyTavern 연결 프로필`이 있으면 우선 사용합니다.
2. 없으면 Connection Manager에서 현재 선택된 프로필을 사용합니다.
3. 모델/키/주소는 기존 SillyTavern 연결 프로필 설정을 그대로 따릅니다.

요청 시 SillyTavern의 `json_schema` 구조화 출력을 사용합니다. 따라서 지원되는 Gemini / NanoGPT(OpenAI 호환) 연결에서는 스키마가 API 요청에 함께 전달됩니다.

## 사용

- **캐릭터**: 이름 + 원본 시트 입력. `현재 캐릭터 시트 가져오기`는 열린 채팅의 **캐릭터 설명과 고급 옵션의 성격 요약만** 채웁니다. 이름·시나리오·첫 메시지·예시 대화는 가져오지 않습니다. `연결 로어북 가져오기`로 기본/보조 로어북 항목을 불러와 복수 선택할 수 있습니다.
- **페르소나**: 이름 + 페르소나 시트 입력. `현재 페르소나 시트 가져오기`로 선택된 페르소나 설명을 채울 수 있습니다. 현재 페르소나에 연결된 로어북이 있으면 항목을 불러와 복수 선택할 수 있습니다.
- **NPC**: 이름 + NPC 시트만 입력합니다.
- 이름은 현재 채팅에서 자동으로 가져오지 않습니다. 캐릭터/페르소나/NPC 모두 사용자가 직접 입력해야 합니다.
- 시트 가져오기는 이름 입력칸을 바꾸지 않습니다. 이미 시트 원문을 입력했다면 덮어쓰기 전에 확인합니다.
- `컴파일`을 누르면 JSON 결과가 표시됩니다. 이 단계에서는 아직 영구 저장되지 않습니다.
- 컴파일 중 표시되는 입력 토큰 수는 글자 수로 계산한 근삿값입니다. 출력 한도는 모델의 내부 사고 토큰까지 포함해 잘리지 않도록 12,000으로 요청하며, 실제 과금은 연결한 API와 실제 사용량을 따릅니다.
- 필요한 결과만 `결과 저장`을 눌러 저장합니다.
- `결과 복사`로 그대로 복사해 검수에 사용할 수 있습니다.
- 결과 아래 `사용된 Source 보기`를 펼치면 각 `source_id`에 대응하는 원문을 확인할 수 있습니다.

## 결과 저장과 삭제

`결과 저장`을 누른 결과는 **SillyTavern 서버의 현재 사용자 프로필 설정 파일**에 저장됩니다. 설정 파일 안의 JSON 경로는 `extension_settings.characterReasoner.savedResults`이며, 확장 코드에서는 `extensionSettings.characterReasoner.savedResults`로 접근합니다. 브라우저의 임시 화면이나 GitHub 저장소에 저장하는 방식이 아니므로 SillyTavern을 새로고침하거나 다시 실행해도 남아 있습니다. 다른 SillyTavern 사용자 프로필과는 공유되지 않습니다. 저장하지 않은 컴파일 결과는 새로고침하면 사라집니다.

저장 단위에는 결과 JSON, 이름·종류·컴파일 시각, 사용한 연결 프로필의 ID/이름/모델, 결과에서 실제 인용한 source 원문이 포함됩니다. API 키는 저장하지 않습니다. 전체 시트나 사용되지 않은 source는 중복 저장하지 않습니다.

같은 `entity_type + entity_name`을 다시 저장하면 새 버전을 추가하지 않고 기존 저장본을 덮어씁니다.

- 상단 `저장된 결과`에서 `불러오기`를 누르면 해당 종류의 탭에 JSON과 source 원문을 다시 표시합니다.
- `복사`는 저장된 JSON을 클립보드로 복사합니다.
- 각 항목의 `삭제`는 그 결과 하나만 삭제합니다.
- `전체 삭제`는 저장된 컴파일 결과를 모두 삭제합니다.
- 삭제 전에는 확인창이 표시되며, 삭제한 결과는 복구할 수 없습니다.

## 현재 출력 종류

- `fact`
- `core`
- `value`
- `relationship`
- `knowledge`
- `reaction`
- `expression`
- `boundary`
- `capability`

각 레코드는 현재 장면 검색에 사용할 `when`, 실제 캐릭터 제약인 `rule`, 원문 강도를 보존하는 `modality`, 출처 추적용 `source_ids` 등을 가집니다.

Compiler 프롬프트는 선택적 요약 대신 source-grounded retrieval records를 만들도록 요구합니다. 작성 지시는 데이터로 실행하지 않고 제외하며, 원문의 관점·강도·불확실성·빈도·AND/OR·부정·조건·시간·역할·대상 범위를 보존합니다. 서로 다른 명제와 knowledge 상태를 분리하고, 최종 점검에서 누락된 in-world 정보를 다시 확인합니다. `knowledge`와 `knowledge_domain`/`knowledge_state`의 조합이 맞지 않거나 `when`이 분석용 메타어이면 결과를 오류로 처리합니다.

시트와 로어북 원문에 `PERSONALITY:`, `LIKES:`, `SKILLS:` 같은 짧은 heading이 있으면 코드가 heading 단위 source로 먼저 분리합니다. 모델은 source 경계와 무관하게 필요한 레코드를 더 나누거나 같은 명제를 합칠 수 있습니다.

## 범위

이 저장소는 먼저 **시트 분해 품질만 검증하기 위한 시험판**입니다. 결과 형식이 안정되면 본 씬판독기의 고급 인물 판정 쪽에 이식하는 것을 전제로 합니다.
