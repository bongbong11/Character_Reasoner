# Character Reasoner

SillyTavern에서 캐릭터·페르소나·NPC 원문을 조립하고, 공홈 AI가 만든 retrieval JSON을 검증해 저장하는 시험 확장입니다.

이 버전은 모델이나 API를 직접 호출하지 않습니다. Connection Manager, API 키, Gemini 분기, 자동 repair도 사용하지 않습니다.

## 설치

SillyTavern의 **확장 → 확장 설치**에서 다음 주소를 사용합니다.

```text
https://github.com/bongbong11/Character_Reasoner.git
```

설치 후 새로고침하면 채팅 입력창 주변에 사람 아이콘이 표시됩니다.

## 사용 순서

1. 캐릭터·페르소나·NPC 탭을 선택합니다.
2. 이름과 시트를 입력합니다.
3. 필요한 로어북 항목을 불러와 선택합니다.
4. **분석 명령문 복사**를 누릅니다.
5. 복사한 명령문을 원하는 공홈 AI에 붙여넣습니다.
6. 저장 이름을 적습니다.
7. AI가 반환한 JSON을 붙여넣거나 `.json` 파일로 불러옵니다.
8. **검증 후 저장**을 누릅니다. 검증을 통과한 결과는 해당 저장 이름 아래에 날짜별 버전으로 저장됩니다.

JSON 코드펜스와 JSON 앞뒤의 짧은 설명문은 저장할 때 자동으로 벗깁니다. 붙여넣기, 파일 선택, 파일 끌어놓기는 입력칸만 채우며 자동 저장하지 않습니다. 사용자가 **검증 후 저장**을 눌러야 저장됩니다.

## 탭별 원문

- **캐릭터**: `현재 캐릭터 시트 가져오기`는 열린 캐릭터 카드의 **설명과 성격 요약만** 가져옵니다. 시나리오, 첫 메시지, 예시 대화는 포함하지 않습니다. 연결된 기본·보조 로어북에서 필요한 항목을 고를 수 있습니다.
- **페르소나**: 현재 페르소나의 이름과 설명을 가져옵니다. 연결된 페르소나 로어북 항목을 고를 수 있습니다. 명령문에는 페르소나가 `{{user}}`라는 안내가 추가됩니다.
- **NPC**: 이름과 상세 시트를 직접 입력하고 선역·악역·양립/혼합 역할을 고릅니다. 전체 로어북 목록에서 필요한 항목을 선택할 수 있습니다. 역할은 검색 맥락으로만 전달되며 설정을 창작하는 근거로 사용하지 않도록 명령문에 적힙니다.

로어북 목록에서는 한 항목씩 선택하거나 전체 선택/해제할 수 있습니다. 비활성 항목도 `비활성` 표시와 함께 보이며 필요하면 선택할 수 있습니다.

## 저장 위치와 묶음 구조

저장 결과는 **현재 채팅방의 chat metadata** 안 `characterReasonerBank`에 들어갑니다. 따라서 다른 채팅방의 결과와 섞이지 않습니다.

저장은 다음 순서로 나뉩니다.

```text
현재 채팅방
├─ 캐릭터
│  └─ 사용자가 적은 저장 이름
│     ├─ 2026-09-29 14:20
│     └─ 2026-09-30 09:10
├─ 페르소나
│  └─ 사용자가 적은 저장 이름
└─ NPC
   └─ 사용자가 적은 저장 이름
      ├─ 2026-09-29 15:00
      └─ 2026-10-02 21:30
```

같은 NPC를 같은 저장 이름으로 여러 번 저장하면 덮어쓰지 않고 날짜별 버전이 계속 쌓입니다. 저장 목록은 캐릭터·페르소나·NPC 태그와 저장 이름을 먼저 보여주고, 펼치면 그 이름의 날짜별 저장 이력이 최신순으로 나타납니다.

각 날짜본에는 다음 정보가 저장됩니다.

- 검증된 JSON records
- entity 종류와 이름
- 저장 시각
- 명령문을 만들 때의 전체 Source 묶음
- `source_set_id`
- NPC 역할
- 생성 경로 `external_ai`

API 키나 모델 정보는 저장하지 않습니다.

## 저장본 관리

- **보기**: 해당 날짜본의 JSON을 현재 탭에 표시합니다.
- **복사**: 해당 날짜본의 JSON을 클립보드에 복사합니다.
- **최신 Source로 다시 만들기**: 그 이름의 가장 최근 Source 묶음으로 새 명령문을 복사합니다. 새 `source_set_id`가 발급됩니다.
- **삭제**: 선택한 날짜본 하나만 삭제합니다. 마지막 날짜본을 삭제하면 그 저장 이름 묶음도 사라집니다.
- **전체 삭제**: 현재 채팅방의 Character Reasoner 저장본만 모두 삭제합니다.

삭제한 저장본은 복구할 수 없습니다.

## 잘못된 결과가 섞이지 않게 하는 검사

**분석 명령문 복사**를 누를 때 선택한 시트와 로어북의 Source 묶음을 고정하고 고유한 `source_set_id`를 만듭니다. 가져온 JSON은 다음 값이 방금 복사한 명령문과 일치해야 저장됩니다.

- `source_set_id`
- `entity_type`
- `entity_name`
- 모든 `source_ids`

그러므로 같은 이름의 예전 명령문 결과나 다른 인물의 JSON을 실수로 붙여넣어도 저장되지 않습니다.

Hard validation은 JSON 구조, 필수 필드, enum, Source ID, knowledge 필드 계약을 확인합니다. `when`은 공백과 대소문자 중복을 정리하고 6단어 초과 cue, 분류명, 명백한 설명문 형태를 제거합니다. 한 record의 cue가 전부 제거되면 그 결과는 저장하지 않습니다. 의미가 바뀔 수 있는 `type`, `target`, 과병합·과분할은 자동 수정하지 않습니다.

## 범위

현재 버전은 검증된 인물 자료 bank를 만드는 단계입니다. Jev 판정, 임베딩 검색, 실제 RP 프롬프트 주입은 아직 수행하지 않습니다.
